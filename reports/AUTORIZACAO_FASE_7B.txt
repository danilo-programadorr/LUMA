==================================================
OBJETIVO DA FASE 7B
==================================================

Transformar controles críticos da LUMA, hoje em memória, em estado
durável e auditável.

Persistir com segurança:

- identidade/principal;
- project registry configurável;
- estado global da LUMA;
- revogações;
- tools habilitadas/desabilitadas;
- approval requests;
- approval records;
- action requests;
- sessions;
- learning candidates;
- audit events;
- configuração operacional permitida.

Criar também uma superfície administrativa LOCAL e autenticada para que,
no futuro, a LUMA Web possa administrar esses controles.

NÃO conectar Gemini.
NÃO instalar Google ADK.
NÃO conectar Calendar.
NÃO conectar Tasks.
NÃO criar agentes executáveis.
NÃO criar frontend.

==================================================
ETAPA 1 — TECNOLOGIA DE PERSISTÊNCIA
==================================================

Para esta fase local, usar uma camada de persistência abstrata.

Preferência:

SQLAlchemy 2.x
+
SQLite local

Justificativa:

- simples para ambiente local;
- transacional;
- reproduzível;
- sem serviço externo;
- adequado à atual escala;
- fácil migração futura para PostgreSQL.

A arquitetura NÃO deve depender de recursos exclusivos do SQLite.

Criar interface/repository layer para permitir futura troca por PostgreSQL
sem reescrever regras de negócio.

NÃO introduzir PostgreSQL nesta fase.
