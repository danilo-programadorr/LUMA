# Owner authentication — 7F-B

2026-10-25. Backend 0.6.0rc1; local candidate based on dc85fa894e2ad99325ef77a937d0f7a8f2a38fe7. Verification: Codex for local/API/database evidence; Owner for real Google login, logout and session restoration. See reports/FASE_7F_B_IDENTITY_PLATFORM_REAL.json for the technical closure gate.

Authentication and authorization are distinct. Official google-auth 2.62.0 verifies Firebase/Identity Platform ID token signatures with public Google certificates and the configured audience. The adapter additionally checks issuer, exact project audience, nonempty UID <=128 characters, integer exp/iat/auth_time, ordering and current time, Google provider and absence of tenant. Email/name/avatar never authorize. Only an ACTIVE persistent google.com + UID binding resolves to the existing internal HUMAN_OWNER. No credentials or raw claims enter audit, error responses or /me.

Explicit LUMA_OWNER_AUTH_MODE: LOCAL_TOKEN (legacy LOCAL_DEV/private administration/tests) or IDENTITY_PLATFORM (Web pilot). Unknown values including TEST fail startup. Tests instead inject an in-process verifier only with LUMA_ENV=test; no HTTP test-login endpoint, no production synthetic-token decoder. Identity mode never accepts the legacy Owner token for Web routes. Runtime/device routes retain their separate existing identities.

Migration 0005 is opt-in: python -m backend.migrate upgrade --owner. Migrations 0001–0004 are unchanged. Existing local baseline schema 4 remains supported; identity auth requires schema 5. New owner_bindings has a database-enforced singleton id=1 and provider/UID uniqueness. A revoked binding cannot be replaced by bootstrap. There is no remote Owner-delete/change API.

Bootstrap: run python -m backend.owner_bootstrap in the Owner's private interactive terminal after real Google configuration is authorized. It prints a random 256-bit-equivalent code once; only SHA-256 digest persists, TTL 300 seconds and maximum five failed attempts. The code is never put in frontend config, files or reports. A valid Google ID token plus that code is required by POST /v1/owner/bootstrap. Binding, code consumption and audit are one serialized transaction; failed attempts commit before denial. Local CLI may rotate an expired/locked unbound code; previous code becomes invalid. Once any binding exists, issuance and bootstrap are disabled, even after revocation. Do not pipe/record terminal output.

GET /v1/owner/me returns internal id, provider, active status and auth freshness only. Missing/invalid token:401; valid non-owner:403. Login never creates approvals, authorizations or jobs. Existing admin confirmation requirements remain independent. Public health is sanitized. Auth-sensitive routes have a process-local 120/minute limit; bootstrap five-attempt protection is durable and survives process restart. Multi-instance distributed throttling is future deployment work.

Recent-auth pilot policy: 300 seconds using auth_time, never iat. Helper and reauthentication button prepare later step-up; no execution is enabled. Browser SDK persistence and refresh are official; no custom token storage. A persistent 401 signs out locally; 403 does not loop reauthentication. Google sign-out does not delete the binding.

Limitations: provider account revocation checks beyond signed-token expiration are not added; local binding status is checked on every request. HTTPS and future origin policy remain required before public deployment. Real login, binding, logout and refresh restoration were confirmed by the Owner; durable binding was inspected without exporting the UID. Windows automatic time synchronization remains unresolved after manual clock correction.
