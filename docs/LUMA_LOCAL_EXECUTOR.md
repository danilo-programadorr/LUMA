# Executor local e arquitetura híbrida

2026-10-23. Adendo incorporado. Prioridade: owner no celular → Web/Control Plane always-on futuro → Job autorizado → PC ligado → Local Executor. Cloud executor é para APIs sem dependência do PC; LOCAL_DEVICE é para recurso local. CLOUD/LOCAL_DEVICE/EITHER constam do envelope autorizado. LOCAL_DEVICE exige device_id exato e nunca muda para cloud/outro PC silenciosamente. EITHER é consentimento explícito; nesta candidata só o caminho cloud/local de desenvolvimento existente é elegível, sem seleção automática de PC.

ExecutionDevice registra owner, tipo WINDOWS, estado, capabilities permitidas, versão, heartbeat, enabled/revoked. Codex/filesystem/git/browser/desktop são planned; somente sandbox-test é habilitado por fixtures. Capabilities anunciadas não ampliam as registradas. Last_seen tem TTL de 60s; ONLINE com capacity livre é necessário. OFFLINE/BUSY aguardam; REVOKED bloqueia com BLOCKED_DEVICE_REVOKED. Expiração/policy/kill switch são verificados novamente antes de READY e do efeito.

POST /v1/execution-devices retorna credencial aleatória de desenvolvimento uma única vez. Banco guarda somente digest e credential_id; listagem e auditoria não retornam segredo. Registrar ID existente não reemite chave; futura rotação usa reenrollment administrativo específico. DeviceCredential prevê secret store. Credential de device não autentica owner/admin/runtime; owner token não autentica heartbeat. X-Luma-Device-ID é apenas seletor, conferido com o digest. Revogação invalida heartbeat/poll imediatamente.

python -m backend.local_executor inicia somente conexões outbound: heartbeat e poll autenticados. HTTPS obrigatório fora de 127.0.0.1; redirects/proxies de ambiente desabilitados. Não abre listener, porta pública ou RDP. Poll é curto, repetido a cada 10s com reconexão; contrato DevicePollRequest prepara HTTPS long polling até 30s. A fila persistente é canônica, não o canal. O cliente de produção não executa TestTool nem adapters mutáveis. Testes de execução sandbox usam processo separado e DB local; testes HTTP provam a autenticação do canal. Não se afirma execução mutável remota em cloud.

Windows Service/autostart, enrollment com identidade forte, rotação, mTLS/opção de device-bound keys e armazenamento DPAPI/Secret Manager são trabalho futuro. LocalResourceScope lista paths exatos e default DENY; não é acesso concedido ao filesystem nesta fase. Codex CLI/browser/desktop permanecem DISABLED. Desktop deve ser HIGH por padrão. Nenhum comando/URL arbitrário é aceito. PC precisa estar ligado para tarefas locais; tarefas cloud futuras não dependerão dele.
